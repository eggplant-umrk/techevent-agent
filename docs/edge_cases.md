## 3. 本番の API で流す代表10件（まだ流していない）

- 対象：依頼ではない3件（R1・R2・R7）、不適切3件（B1・B3・B4）、判断が要る2件（J1・J2）、形の崩れ2件（F3・F4）
- 流れ：受信箱に貼ったときと同じ（読み取り → 候補づくり → 声かけ文と主催者への返事）。受信箱と実行時のデータは一時フォルダに書き、カードには書き戻さない
- 記録：段階ごとに、読み取れた項目・候補の人数と文・ツールの呼び出し・差し戻しの回数・下書きと返事・金額。一覧の「出てはいけない言葉」（暴言の写し、個人情報、性別や年齢の推測、競合の実名での比較、誤った開催日）が各段階の文に出たかをコードで見る。結果は `docs/edge_cases_result.json`
- 金額：見込み 約 $1.0〜1.4。上限（既定 $1.5）を超えそうなら、その件を流さずに止まる。10件すべての読み取りと候補づくりを優先し、下書き（重いモデル）は残りの件数の分を取り置いて余裕があるときだけ作る
- 流していない理由：このスクリプトは API キーを `.env` から読む。作業場所（worktree）に `.env` はなく、main の作業場所の `.env` を指して流そうとしたところ、権限の確認で止まった（`.env` は読まない、の指示に当たる）。キーの渡し方を決めてもらえれば流せる

## 4. 直し方の案（直すのは別の作業）

| 対象 | 案 |
| --- | --- |
| 依頼ではない入力（R1・R4・R5・R6・R7） | 読み取りの呼び出し（小さな1回）に「登壇の依頼か」の項目を足し、依頼でなければ候補づくりを始めない。受信箱の1件に種類（依頼／依頼ではない／対応に注意）を持たせ、一覧で見分けられるようにする。記号だけ・URL だけは、文字の種類を見て API の前に止める |

| 主催者への返事の検査（B4・J1・J3・B1） | `lib/organizerReply.ts` に、個人情報（住所・電話番号・年収・給与）、属性（性別・年齢・国籍）、社外秘（未発表・売上・解約率）の言い方を足す。返事は確かめた項目だけで作っているので、項目にない言葉が出たら止める形（使ってよい言葉を決める）のほうが、禁止の言葉を足し続けるより漏れにくい |

## 5. 関所を入れたあと（2026-11-22、feature/intake-gate）

受信箱に貼られた文が登壇の依頼ではないとき・不適切なときに、候補づくりを走らせない「関所」を入れました。種類の判定は AI（今の読み取りの1回に足しただけで、呼び出しの回数は同じ）、止める・表示する・注意を足すのはコードです。

### 日付の読み方を差し替えた（lib/intake.ts の checkDate）

③が lib/dateHint.ts に入れた日付を読む関数を使うようにした（lib/dateHint.ts そのものは変えていない）。

- 日付は `decideDate(quote, receivedAt)` で決める（今までの lib/dates.ts の findDates はやめた）。英語の月名・ピリオド区切りを読み、「12月15日、16日」は2つ、暦にない日付（2月30日）は決めない
- 「候補」「未定」などの言い回しは、今までどおり NOT_FIXED で見る
- 決まったら `otherDatesInConversation` で会話全体を見る。**引用の後ろ**に別の日付が1つでもあれば未定にする（理由に別の日付を書く）。引用の前だけなら、決めた日のまま（N2 のように、あとのメッセージで決まった日程を使う）
- 引用の後ろの別の日付でも、すぐ近く（前後15字）に「予備日・締切・〆切・応募・申込・公開・募集」などがあるものは数えない（開催日ではないため）。「開催は2027/1/29です。予備日は2/5」は今までどおり 1/29 に決まる
- 引用に「書いてしまい・書き間違い・誤り・誤記・誤植・間違い・訂正」があれば未定にする（NOT_FIXED に足した）。チラシの誤りを引用されたときに、その日で決めないため
