## 残したもの（見た目だけでは直せない・決めが要る）

| 何が困るか | 残した理由 |
| --- | --- |
| `?mock` で、貼った会話に関係なく同じ結果が出る（明日 #1 の残り） | 画面に「モックでは保存済みの結果を出しています」は出している。キーワードで近い例を選ぶのはモックの作り直しになる |
| 候補の要約・指名の評価が長い | Agent の文の長さ（指示文）を変えることになる |
| 柚木さんの候補の「指名の代わり」「条件付き」と本文の食い違い | Agent の出した印と文の中身の問題（データ・指示文） |
| 「この人で進める」で、送る前に「声かけ中」になる | 状態の決め方（承認の記録のタイミング）を変える。結合テストの動きにも関わる |
| `?mock` で再読み込みすると、貼った依頼や承諾が消える | モックの状態をブラウザに保存する作りが要る。案内に「再読み込みすると最初に戻ります」と書くのが早い |
| 人の一覧の上のボタンの多さ（入口を右のパネルにまとめる） | ボタンの文字は短くしたが、置き場所を変えるのは画面の組み替えになる |
| イベントの「需要ありを提案」をカードへのリンクに | イベント単位の集計（overview）に、どのカードかが入っていない。窓口を変えることになる |
| 新しいテーマ案を「話せるテーマ案」のすぐ上に動かす | 言葉は直した。置き場所はカード詳細の組み替えになる |
| 出し先の注意点の色を「引っかかる点」1行だけに | 2つまでにした。色の決め方は出し先の画面全体の見直しになる |
| ネタ帳の更新の作業ログを右のパネルに出す | 終わったらたたむようにした。置き場所の変更は画面の組み替えになる |
| 最近の活動に「typo修正」などネタにならない活動が並ぶ | ネタ帳の更新でコードが落とした活動の記録を画面に渡す必要がある |
| 発信の記録の架空のリンク（example.com）が押せる | 架空のブログ記事ページ（/blog/{id}）につなぐか、押せなくするかの決めが要る |
