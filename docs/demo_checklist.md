## 3. 発表

| やること | 操作 | 確かめること |
| --- | --- | --- |
| Google Meet に入る | 案内の Meet のリンクから入る | 自分の名前で入れている |
| マイクとスピーカーを切る | Meet の下のマイクのボタンを切り、PC の音量を消す（会場の音とぶつからないように） | マイクのボタンに斜線。PC の音が出ない |
| 画面共有 | Meet の「画面を共有」→ 発表用のブラウザのウィンドウ（またはタブ）を選ぶ。画面全体は選ばない | Meet に発表用の画面だけが映る。ターミナル・エディターは映らない |
| 自分の発表の間だけ見せる用を止めるか | 先に決めておく（下）。止めるなら①がターミナル2で Ctrl+C、発表が終わったら `npm run start:share` | 止めたなら `netstat -ano \| findstr :3100` に LISTENING が出ない。再開したら最初の行が出る |

見せる用を止めるかの考えどころ：

- 止めない：参加者は発表の間も触れる。発表用とは別のサーバー・別の置き場なので、参加者の操作が発表用の画面に出ることはない。ただし **API のキーは同じ**なので、参加者が同時にたくさん使うと、発表用の候補づくりが「AI が混んでいます」「AI の利用が一時的に混み合っています」になることがある
- 止める：発表用の API が混みにくくなる。止めている間、参加者の画面は開けない。起動し直しても合言葉・リンク・参加者の記録はそのまま（IP が変わらなければリンクも同じ）

## 4. 困ったとき

| 起きたこと | すること |
| --- | --- |
| API が混んでいる（「AI が混んでいます」「AI の利用が一時的に混み合っています」が出た・候補が出ない） | 少し待って「もう一度探す」。だめなら発表用の画面を http://127.0.0.1:3000/?mock に切り替えて、保存済みの結果で続ける（`?mock` は API を使わない） |
| Wi-Fi が切れた・つなぎ直した | 見せる用のアドレス（IP）が変わることがある。つなぎ直したら /share-links を開き直し（映さない）、新しい「一般用のリンク（Notion に貼る用）」を Notion に貼り替え、「メンター・審査員用のリンク（運営さんに渡す用）」を運営さんに渡し直す（Notion にもスライドにも出さない）。見せる用のサーバーの起動し直しは要らない。参加者は新しいリンクから入り直す（前のアドレスで入った印は使えず、試せる分も新しいアドレスで数え直しになる）。発表用は 127.0.0.1 なので開けるが、API には Wi-Fi が要る |
| 金額の記録が壊れた（「金額の記録が読めません（壊れていたので … に退けました）」が出て、API を使う操作が止まった） | その場では直さず、`?mock` で続ける。退けたファイルの中身を確かめて片付けるのは、発表のあとに① |
| 見せる用の上限に届いた | 見せる用の候補を出す・分析・下書き・ネタ帳を更新が止まり、画面に理由が出る。見るだけの操作と `?mock` は続けられる。上限は上げない |

見せている間の上限の動き：上限（SHARE_BUDGET_USD）を超えると、API を使う操作は止まり、画面に理由が出ます。側ごとの合計の上限（SHARE_GENERAL_POOL_USD・SHARE_MENTOR_POOL_USD）に届いた側は、その側だけ止まります（一般の参加者が使い切っても、メンター・審査員は続けられる）。1人あたりの上限（SHARE_PER_PERSON_USD）を超えた人は、その人だけ「この端末で試せる分を使い切りました。保存済みの例（?mock）は引き続き見られます」になります。API を使う操作が同時に2件を超えたときは、最大60秒待ってから理由を出して断ります。
