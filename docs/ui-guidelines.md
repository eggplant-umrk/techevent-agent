# UIガイドライン（ネタ帳Agent）

方向性：LayerXらしい、シンプルな業務ツール。飾らず、情報が速く読めて、迷わず押せること。
参考モック：https://claude.ai/artifact/4ZCHXbjVpiiP4hLCS1XEwg（メイン画面）

## 色
| 用途 | 色 |
|---|---|
| 背景 | #F5F6F8 |
| 面（カード・パネル） | #FFFFFF、枠線 #E3E6EB、角丸 12px |
| 本文 | #1B2330 |
| 補足の文字 | #5B6472（白地でもコントラスト4.5:1以上） |
| アクセント（主ボタン・リンク・選択中） | #1D4FD7、薄い背景 #EEF2FD |
| 未発信・注意 | 文字 #8A4B00、背景 #FFF4E5 |
| 確認済み・完了 | 文字 #157347、背景 #E8F5EE |
| 中立のタグ | 文字 #3A4250、背景 #EEF0F3 |

- アクセントは青の1色だけ。グラデーション、左だけ太い枠線のカード、絵文字は使わない
- 状態は色だけで伝えず、必ず文字のラベルを付ける

## 文字
- Inter ＋ Noto Sans JP
- 見出し 16〜18px／700、本文 14〜15px、補足 12〜13px、行間 1.5〜1.6

## レイアウト
- 上部ヘッダー：アプリ名と、タブ3つ（受信箱／ネタ帳／アーカイブ）だけ。金額は ?debug のときだけ右端に出す
- 余白は8の倍数。カード内の余白は16〜20px。狭い画面では縦に積む

## タブ（いつ使うか で分ける。機能は増やさず、今あるものの置き場所を決める）
| タブ | いつ使う | 置くもの |
|---|---|---|
| 受信箱（最初に開く） | 依頼が届いたとき | 左：受信箱の一覧（開催日が過ぎた依頼は出さない）。右：依頼パネル（依頼 → Agentがやったこと → 候補 → 承認 → 声かけ文 → 結果の記録）。サンプルの依頼と「手で追加」もここ |
| ネタ帳 | 人を知りたいとき・ネタを育てるとき | 左：人の一覧（名前・得意分野・未発信のネタの数・予定の埋まり具合）。右：人の詳細（人の情報と直す、予定の埋まり具合（lib/busyness.ts の言葉）と今後2週間の予定（日ごとの時刻だけ。タイトルは出さない）、その人のカード、最近の活動）。「ネタ帳を更新」「ブログのネタを出す」もここ |
| アーカイブ | イベントが終わったあと | 左：終わったイベントの一覧（開催日が過ぎた依頼と、過去のイベント）。右：過去のイベントならイベント後の画面（日付・登壇者・アンケートの取り込み・集計・分析・ネガティブとポジティブ・カードへの書き戻し）、過去の依頼なら日付・登壇者・依頼の結果。以前のヘッダーの「依頼／イベント」の切り替えはこのタブに置き換えた |

- カード詳細（シート）はどのタブからでも開ける。中身（出し先を探す・テーマ案の採用/見送り・カードを直す）は変えない
- 人の一覧の1行：名前・所属／得意分野（3つまで）／未発信のネタの数／予定の埋まり具合（「予定 7割」。予定が分からなければ「予定 不明」、言葉は行に重ねたときに出す）。印は「今は控えたい」「確認済み」だけ
- 登壇経験の言い方は候補の印（初登壇／半年以内に登壇／登壇経験あり、lib/talkTag.ts）にそろえる。絞り込みも「初登壇」
- 人の情報を直す：得意分野、登壇の意向（今は受けられる／今は控えたい／未確認）、NGのテーマ。直した項目は「確認済み」になり、Agentは上書きしない。候補を出すときは意向とNGのテーマを使う
- 開催日が過ぎたかどうかはコードで判定する（依頼の開催日。本文しかない依頼は、本文の日付から読む）
- 引き算：一覧には数字と印を必要なものだけ出す（申込数・来場数・金額などは出さない）

## 部品
- カード一覧の1行：名前・所属・最新の活動日／テーマ案1行／タグ（未発信・登壇0回・LT向き・確認済み など）
- 依頼パネル：依頼の要約 →「Agentがやったこと」（番号つきの手順と、何で判断したか）→ 候補（0〜5人、登壇経験の印つき）
- 候補カード：順位、名前、テーマ案（太字）、理由1〜2行、根拠のリンク（クリックで元の投稿へ）、注意点のタグ、「この人で進める」（主ボタン）と「カードを見る」
- 声かけ文：編集できるテキストエリア。送信ボタンは置かず「コピー」だけ。「自分の言葉に直して送ってください」と添える
- 結果の記録：承諾／辞退をボタンで選び、辞退なら理由（テーマが合わない／忙しい／予定が重なる／その他）をボタンで選ぶだけ
- 確認済みカードへの新しい提案：「新しいテーマ案（未確認）」の印と「採用」「却下」ボタン
- 候補がいないとき：無理に並べず、「見つからない理由」と「次に確認すべきこと」を表示

## 使いやすさとアクセシビリティ
- 押せるものは本物の button か a。タップ領域は高さ40px以上
- アイコンだけのボタンには aria-label
- 処理中は作業ログが順に増えていき、待ち時間が分かる
- エラーは何が起きて次に何をすればいいかを1文で出す
