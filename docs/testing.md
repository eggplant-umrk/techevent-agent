# テストの層

テストを4つの層に並べています。下の層ほど速くて数が多く、上の層ほど本物に近くて少ないです。どの層も**本物の API・Slack は使いません**（秘密の値も .env も要りません）。

| 層 | 命令 | 何を守るか | 速さ（手元の目安） | モックの多さ |
| --- | --- | --- | --- | --- |
| 1. ユニット | `npm run test:unit` | 関数ひとつひとつの決まり（日付の読み方・関所・候補の検証・金額の計算・Slack の受け取りなど）。壊れた場所がすぐ分かる | 約1分（25本） | 多い。API は偽物の関数に差し替え、置き場は一時フォルダ（`scripts/_isolate.ts`） |
| 2. API | `npm run test:api` | 窓口（`/api/…`）の約束。本物のサーバーに本当に要求を投げて、返り値と置き場（一時フォルダ）の変化を見る | 約2分（ビルド込み）、ビルド済みなら約40秒 | API だけ偽物（偽の Anthropic サーバー）。サーバー・入口（proxy）・保存は本物 |
| 3. E2E | `npm run test:e2e` | 画面でデモの流れが通ること（貼る → 候補 → 声かけの下書き → 承諾 → アーカイブ → ネタ帳） | 約2分（ビルド込み）、ビルド済みなら約20秒 | API だけ偽物（1本）／`?mock` の画面（1本） |
| 4. 評価 | `npm run test:eval` | 保存済みの Agent の結果が、守るべき決まり（根拠が実在する・送信しない・候補の情報を Slack に出さない など）を満たすこと。④の保つ評価が90%以上 | 約10秒 | なし（保存済みの本物の結果をコードで判定） |

まとめて流す命令：

| 命令 | 流す層 | 使いどころ |
| --- | --- | --- |
| `npm test` | 1 → 2 → 4 | ふだん。コミットの前 |
| `npm run test:all` | 1 → 2 → 3 → 4 | 画面に関わる変更のあと・main に入れる前 |
| `npm test -- inbox stage` | 1（名前にその言葉が入るものだけ） | 直している場所のテストだけ（前と同じ） |

- 1つの層が失敗しても、残りの層は流して、最後に層ごとの結果（○×と秒数）を出します（`scripts/test_layers.mjs`）
- API 層と E2E 層は本番用のビルド（`next build`）を使います。まとめて流すときは最初に1回だけビルドして使い回します。続けて流すときは `SKIP_BUILD=1` を付けると、すでにある `.next` を使います
- 4 の評価は、前からの結合テスト（`eval --offline`）と、④の評価（docs/evals.md）のうち API を使わない保つ評価（`eval:keep`）です

## 1. ユニット

`scripts/test_*.ts` を全部（中身は前のまま）。名前で選ぶときは `npm run test:unit -- inbox`。1本だけなら `npx tsx scripts/test_inbox.ts`。

## 2. API（`tests/api/api.test.mjs`）

1. 偽の Anthropic（`scripts/testing/fake_anthropic.mjs`）を空いているポートで立てる
2. 本番用のビルドで、本物のサーバーを2つ立てる（`scripts/serve.mjs` を通す。本物と同じ入口）
   - 3201番：発表用（合言葉なし）。`API_TIMEOUT_MS=5000`
   - 3202番：見せる用（`--share`。合言葉と `SHARE_BUDGET_USD=0.03`）
   - 始まりのポートは `TEST_API_PORT` で変えられる。3000番・3100番は使わない（使おうとすると止まる）
3. 窓口に要求を投げて、返り値と置き場の変化を見る

| 試験 | 見ること |
| --- | --- |
| 依頼を貼る → 候補が出る | `POST /api/inbox` → id、準備が終わって ready、候補が1人以上（名前・テーマ・根拠）、偽の API に読み取りとループが届いた、置き場の inbox.json・usage.json に書かれた、同じ文は足さない |
| 依頼ではない文で止まる | URL だけは 400 で API を呼ばない。雑談は「依頼ではない」になり、候補を探すループを呼ばない |
| 承諾と取り消し | 進める → 承諾 → 依頼の状態と置き場の cards.json に出る、2回押しても1つ、取り消すと消える、承諾がないのに取り消すと 400 |
| 合言葉 | なしの窓口は 401、画面は合言葉の画面へ、違う合言葉は 401、正しい合言葉で印（cookie）、ヘッダーでも通る、置き場が発表用と別 |
| 予算の上限 | 上限まで使える → 使った分が上限を超える → API を使う操作は 429（偽の API も呼ばない）、見るだけの窓口は使える |
| 時間切れ | 偽の API が返事をしない → 約10秒でエラー「AI の返事が5秒なかったので止めました」、そのあとの依頼は準備できる（枠が戻る） |

最後に、リポジトリの `data/` が変わっていないこと（書いたのは一時フォルダだけ）も確かめます。失敗したときは、サーバーの記録の場所を出します。

## 3. E2E（`tests/e2e/`、Playwright）

- `playwright.config.ts` の webServer が `scripts/testing/serve_for_e2e.mjs` を起動する（偽の Anthropic ＋ 本物のアプリの本番用ビルド、3211番。`E2E_PORT` で変えられる。置き場は一時フォルダ）
- `demo_fake_api.spec.ts`：偽の API で、貼る → 候補 → 声かけの下書き（偽の API の文）→ 承諾 → 開き直しても残る → アーカイブ → ネタ帳（その人に「承諾済みの依頼あり」）
- `demo_mock.spec.ts`：`?mock` で同じ流れ。モックでは貼った会話は「候補なし」になる作りなので、貼ったあとは例の依頼「フロントエンド広場」で続ける。モックは元のデータを GET の窓口で読むだけで、`/api` に書き込まない（POST などを送らない）ことも確かめる
- 画面の要素は、役割（ボタン・見出し・領域など）と見える文字で探す（`tests/e2e/helpers.ts`）。クラス名や見た目が変わっても壊れにくい。画面の文言を変えたら helpers.ts を直す
- 失敗したら、画面の写真とトレースが `test-results/` に残る（`npx playwright show-trace test-results/…/trace.zip`）
- 初めて流すときは、ブラウザを入れる：`npx playwright install chromium`
- 手元では、3211番で立っているサーバーがあれば使い回す（CI では毎回立てる）

## 4. 評価

- `scripts/eval.ts all --offline`：保存済みの結果の判定（69件）
- `scripts/evals/run.ts keep`（= `npm run eval:keep`）：④の保つ評価。90% を切ったら失敗
- ④の上げる評価が main より下がっていないか（`eval:compare`）は `origin/main` と比べる作りで、CI の浅い checkout では比べる相手がないことがあるので、ここには入れていません。`npm run test:evals`（ユニット）が、形・点数の計算・保つ評価・上げる評価が下がっていないことを見ます
- API を使う評価（`npm run eval`・`npm run eval:passk`・`npm run try:edge`）はお金がかかるので、テストには入れていません

## 偽の Anthropic（`scripts/testing/fake_anthropic.mjs`）

いじわる試験の `scripts/abuse/fake_api.mjs` を土台に、ふつうに答えるモード（ok）を足したもの。届いた要求の形を見て、本物と同じ形の返事を返します（アプリのコードは変えていません）。

- 候補を探すループ：1回目に、最初の指示に出てくるカードを `get_card` で見る → 2回目に、その結果の根拠だけで `submit_candidates`（2人まで、条件付き）。差し戻されたら理由をメモに残して終える
- 会話の読み取り：「」のイベント名・日付の一節・LT などを拾う。登壇・LT・依頼・お願いなどの言葉がなければ「依頼ではない」
- そのほか形の指定があれば形どおりの値、なければ決まった文（「試験用の偽の API の文です」が入る）
- 使った分は毎回 入力1,000・出力500 トークン（金額の上限の試験に使う）
- モード：ok／429／529／500／hang（返事をしない）／badjson。試験の途中で `setMode` で切り替える

## 本物のサーバーを立てるときの守り（`scripts/testing/app_server.mjs`）

- `.env` は使わない：アプリが読む環境変数の名前をソースから集めて、すべて空にしてから必要なものだけ入れる（`.env` の読み込みは、すでにある環境変数を上書きしないため、本物のキー・Slack・カレンダーの URL が混ざらない）。キーは `sk-ant-fake-…`、宛先は偽の Anthropic
- 置き場（受信箱・下書き・カード・金額の記録など）は一時フォルダ。終わったら消す
- 3000番・3100番は使わない
- **本番用のサーバー（`npm start`・`npm run start:share`）が動いているとビルドしない**：`next build` は `.next` を作り直すので、同じ作業場所で動いている本番用のサーバーを壊すため（開発サーバーの `.next/dev` は残るので、`npm run dev` とは一緒に流せる）。別の作業場所のサーバーだと分かっているなら `TEST_ALLOW_BUILD=1` を付ける。発表の当日は main の作業場所でテストを流さない

## CI（`.github/workflows/ci.yml`）

push と pull request のたびに、3つの仕事を並べて流します。秘密の値は使いません。

- check：型チェック → ユニット → 評価
- api：API 層（ビルド込み）
- e2e：Playwright の Chromium を入れて（`npx playwright install --with-deps chromium`）E2E 層。失敗したら画面の写真とトレースを残す（7日）
